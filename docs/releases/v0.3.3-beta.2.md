## Product contract

Public Alpha remains the canonical Ask WTF experience. Member Beta adds its
authenticated, owner-scoped capabilities inside that experience; it must not
introduce a parallel dashboard, fake review fixture, or a replacement chat
shell.

## Included in this candidate

- Alpha-compatible member conversation framing and overflow-aware composer
  behavior, while public Alpha routes retain their existing behavior.
- Private, Clerk-authorized member sessions with owner-scoped history,
  explicit-memory provenance, archive, and confirmed deletion.
- Bounded member conversation navigation and message retrieval, with private
  context kept separate from the public retrieval contract.
- Source-backed Ask WTF answers: published/uncut scope, citations, abstention,
  and truthful fallback remain the shared inference boundary.
- Member Settings and operator/super-admin RBAC remain separated by server-side
  authorization rather than UI visibility alone.

## Explicitly held

- No `/beta/preview`, browser-only fixture, seeded acceptance data, or
  authentication bypass is valid for this candidate.
- No automatic context summarization is introduced without a separately tested
  policy, checkpoint lifecycle, and provenance model.
- No corpus, Vectorize, R2, D1, Clerk, Cloudflare resource, DNS, queue,
  deployment, Public Alpha, or production state change is included.
- Real staging acceptance still requires invited two-member and super-admin
  Clerk/D1 verification in the in-app browser after an owner separately
  authorizes that external operation.

## Promotion gates

1. Local Cloudflare, web unit/contract, typecheck, lint, build, privacy, and
   diff checks pass against the final commit.
2. Alpha public-route regression evidence confirms no component or navigation
   drift.
3. Staging proves the real identity and role matrix with no fixture fallback.
4. An owner authorizes a specific PR, merge, and deployment action.
