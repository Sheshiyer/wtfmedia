# WTFMedia v0.3.0-alpha.1

## Episode-scoped dual-source Ask WTF

This alpha packages the current localhost work into a named, reviewable
release candidate for WTF OS. It joins the public catalogue, episode-scoped
Ask WTF, approved uncut evidence, source-aware citations, and the operator
control-plane additions under one release identity.

### Included

- `published`, `uncut`, and `both` retrieval modes with per-source mode
  preserved through mixed results and truthful fallback behavior.
- Validated public `episodeId` routing, Vectorize episode filters, and a
  post-retrieval membership check that prevents unrelated evidence leakage.
- Public episode surfaces that identify approved uncut evidence as indexed for
  episode-scoped Ask WTF while keeping playback and alignment explicitly held.
- Frame.io metadata propagation from approved uncut jobs into every generated
  uncut Vectorize record, with HTTPS host allowlisting at projection and web
  boundaries.
- Source-panel behavior that shows Frame.io source links for uncut citations,
  published YouTube links for published citations, and timestamps only when
  the returned source is mapped.
- Deterministic uncut reconciliation tooling: 43 timestamp sidecars plus six
  metadata-only refresh jobs for approved untimed transcripts.
- Keyboard-safe navigation cleanup, removal of the stale bottom-navigation
  pill, local RAG fallback coverage, and the calendar API/control-plane work.
- Updated release documentation, architecture receipts, contract manifests,
  focused tests, and the gated GitHub release workflow.

### Explicitly not included

- Raw PDFs, transcript text, local planning input dumps, secrets, or machine
  paths.
- Cross-timeline timestamp alignment, synchronized playback, or a claim that a
  Frame.io URL is itself a seekable timestamp mapping.

### Promotion gates

1. Run the repository verification workflow on the release tag.
2. Create the GitHub Release from this note after all required checks pass.
3. Promote the exact tagged source through the separately gated production
   deployment process, using the repository's approved Wrangler profile and
   deployment receipts.
4. Re-run the live `/api/chat` header probe and record the deployment receipts.

The alpha tag is a source/release identity; it does not by itself assert that
the production web bundle or all background ingest jobs have completed.
