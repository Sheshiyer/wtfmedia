## Evidence classification

This checklist keeps source, environment, and acceptance evidence separate:

| Marker | Meaning | Can satisfy a staging or production gate? |
|---|---|---|
| `VERIFIED-SOURCE` | Reproducible from this checkout with Git or local commands | No, unless the gate is explicitly source-only |
| `STAGING-DEPLOYED` | Exact source candidate is deployed to its changed staging service and paired runtime versions are receipted | Only the named staging gate |
| `REPORTED` | Supplied in a handoff or conversation without a host-visible receipt | No |
| `STAGING-LIVE` | Canonical staging hostname/TLS/ingress proof and signed-out behavior are verified for that candidate | Only the named staging gate |
| `STAGING-OBSERVED-PARTIAL` | Real persona/runtime observation for partial matrices only | No |
| `STAGING-BLOCKED` | Functional blocker remains open and blocks the named gate | No |
| `REPORTED-SUPERSEDED` | Prior report remains in the chain but cannot be used as active evidence | No |
| `STAGING-ACCEPTED` | Exact deployed revision, environment receipts, and real authenticated IAB observations | Only the named staging gate |
| `PRODUCTION-ACCEPTED` | Owner-authorized production evidence for the exact deployed revision | Only the named production gate |
