# Phase 1 — UI Design Contract

> Visual and interaction contract for Compatibility + Component Proof Harness. Generated by gsd-ui-researcher; the checker upgrades `status` only after all six dimensions pass.

---

## Authority and Phase Boundary

This contract is prescriptive. When sources differ, apply them in this order:

1. `01-CONTEXT.md` and the amended Phase 1 entry in `ROADMAP.md` lock the current phase boundary and decisions.
2. `REQUIREMENTS.md` and `ISA.md` define acceptance.
3. `DESIGN.md`, `PRODUCT.md`, `APP-FLOW.md`, and `COMPONENT-INVENTORY.md` define visual, narrative, flow, and component authority.
4. `01-RESEARCH.md` supplies implementation defaults where the authorities leave discretion.
5. Current source is the compatibility baseline to be captured before migration, not permission to preserve known accessibility or privacy defects.

Phase 1 visibly redesigns `/`, `/episodes`, `/connections`, and `/chat` through one repository-owned WTF system while keeping their URLs, public meaning, data semantics, navigation destinations, bookmarks, supported query parameters, deep links, and behavior intact. `/api/chat` remains a frozen compatibility contract. The first proof slice is `EpisodesBrowser` with `ScrollRail` and a URL-backed accessible episode drawer.

Phase 1 does not create `/episodes/:id` or an `episodes/[episodeId]/` route. Those path-segment references in older `APP-FLOW.md` and `DESIGN.md` diagrams describe future architecture, not the current compatibility baseline; the locked Phase 1 drawer decision and the repository's existing `/episodes` route take precedence.

This phase does not add `/ops`, authentication, operator fields, private assets, workflow actions, dossiers, production records, external-service changes, deployments, corpus mutations, or later-phase capabilities. Every rendered datum and fixture is public-only and privacy-safe.

## Design System

| Property | Value |
|----------|-------|
| Tool | Repository-owned semantic CSS custom properties plus Tailwind CSS 3 aliases; no shadcn visual layer |
| Preset | Not applicable |
| Component library | Repository-owned WTF wrappers; selectively use Radix Dialog behavior beneath `Drawer` after the approved implementation plan owns the dependency |
| Icon library | No Phase 1 icon dependency; retain the repository `Sparkle` and wordmark brand glyphs, with text labels for controls |
| Fonts | Bricolage Grotesque for display/labels, Fraunces for editorial moments, Poppins for body and controls |

Detected state on 2026-08-19: no `components.json`, no shadcn preset, no existing `web/components/ui` layer, and no project skill directory. Existing globals and Tailwind configuration contain the committed palette and fonts but still rely on raw color values, perpetual motion, pointer-only drag, and native-cursor suppression. Phase 1 converts those behaviors to semantic contracts without changing the framework or Tailwind major.

Shadcn initialization is intentionally not requested: approved `DESIGN.md` explicitly requires selective unstyled Radix behavior and rejects the default shadcn visual layer. Package installation remains an implementation-plan checkpoint, not UI-spec work.

### Visual Direction

- The product reads as one WTF publication with four purposeful editorial rooms, not one repeated dashboard template.
- Warm cream paper and dense ink structure dominate. Tactile print character comes from typography, borders, offset depth, halftone texture, composition, and selective motion.
- Preserve the extruded lowercase WTF wordmark as a brand asset. Do not generalize its extrusion into ordinary headings.
- Use sharp editorial blocks, never glass panels, indigo gradients, neon AI glow, decorative bento grids, or generic white-card dashboards.
- A divider, spacing, or background change is preferred to a card when no interaction or independent surface boundary exists.
- Public pages may be expressive and image-led; controls, evidence, state, and reading surfaces remain aligned and predictable.

### Component Dependency Rule

`tokens -> primitives -> patterns -> public domain components -> PublicShell`

Only components consumed by the four protected routes ship in Phase 1:

| Layer | Phase 1 contract |
|-------|------------------|
| Foundations | `WtfTokens`, `WtfTheme`, `Typography`, `FocusPolicy`, `MotionPolicy`, `AvailabilityState`, `SyntheticFixtures` |
| Primitives | `Button`, `IconButton`, `LinkButton`, `Drawer`/`Dialog`, `Skeleton`, `Alert`, `LiveRegion`, `SkipLink` as consumed |
| Patterns | `PublicShell`, `ScrollRail`, `GraphWithList`, `SourcePanel`, route state surfaces |
| Public domain | `EpisodeCard`, `EpisodeDrawer`, `AskComposer`, `ConversationThread`, public connection details |
| Deferred | Data-table infrastructure, TanStack Table, Phosphor Icons, operator shell components, and speculative primitives with no Phase 1 consumer |

## Spacing Scale

All spacing uses the permitted set `4, 8, 16, 24, 32, 48, 64`.

| Token | Value | Usage |
|-------|-------|-------|
| `space-1` | 4px | Inline icon/text separation and micro-offsets |
| `space-2` | 8px | Compact control gaps and chip/control padding |
| `space-4` | 16px | Default element spacing and mobile gutters |
| `space-6` | 24px | Panel padding and section clusters |
| `space-8` | 32px | Major component separation |
| `space-12` | 48px | Compact page-section breaks |
| `space-16` | 64px | Standard and large editorial section breaks |

Exceptions:

- Interactive targets are at least 44px by 44px; 44px is a target-size contract, not a layout-spacing token.
- Primary content width is capped at 1400px. Reading copy is capped at 65ch; the drawer transcript is capped at 72ch within its panel.
- Page gutters are 16px at 320px, 24px at 768px, and 32px at 1440px.

### Shape and Depth

| Token | Value | Usage |
|-------|-------|-------|
| `radius-control` | 8px | Inputs and compact controls |
| `radius-panel` | 16px | Drawers, alerts, and working surfaces |
| `radius-card` | 16px | Interactive media cards only |
| `radius-pill` | 999px | Chips and compact actions only |
| `border-strong` | 2px ink | Primary surface and control boundary |
| `depth-card` | 4–6px ink offset | Brand-critical interactive media card |

Hover may increase offset depth by at most 3px and translate by the same distance in the opposite direction. Under reduced motion, depth may change without translation. Drawers use one overlay and one bounded ink edge. Texture stays on fixed paper surfaces, never inside scrolling transcript, message, or data containers.

## Typography

The interface declares exactly four sizes and two weights. The wordmark is a brand asset and is not an interface text-weight token.

| Role | Family | Size | Weight | Line Height |
|------|--------|------|--------|-------------|
| Label | Bricolage Grotesque | 13px | 700 | 1.4 |
| Body | Poppins | 16px | 400 | 1.5 |
| Heading | Bricolage Grotesque | 34px | 700 | 1.2 |
| Display | Bricolage Grotesque | `clamp(40px, 6vw, 72px)` | 700 | 0.95 |

Typography rules:

- The only interface weights are regular 400 and bold 700.
- Fraunces uses the 16px or 34px role at weight 400 for quotations, episode framing, and short editorial explanation. It never appears in buttons, filters, navigation, dense labels, or status UI.
- Body and control text never drops below 16px. The 13px label role is restricted to nonessential metadata, eyebrow labels, and compact state labels with sufficient contrast.
- Labels in uppercase use at least `0.08em` tracking. Headings use balanced wrapping; prose may use pretty wrapping.
- Numbers use Poppins with tabular numerals. Technical identifiers use the system monospace stack without introducing another branded family.
- Long prose remains left aligned; centered type is limited to short empty-state or closing-CTA copy.

## Shared Public Shell Contract

- Keep the canonical wordmark link first in the header. Include a visible skip link targeting main content.
- Mark the active route with `aria-current="page"` plus an ink boundary or underline; color is supplementary.
- Use semantic links for navigation and source opening, buttons for in-place actions, and never clickable generic containers.
- The footer contains public brand and navigation only. Remove model names, retrieval engine names, internal version labels, private paths, operational health, and infrastructure claims.
- Client-side route changes place focus on the destination `h1` after navigation. Browser back/forward restores the browser's expected scroll and focus context when possible.
- Native cursor behavior is always present. An optional decorative cursor may appear only on fine-pointer desktop devices, must not set `cursor: none`, and is disabled for reduced motion, forced colors, coarse pointers, and touch.
- Decorative sparkles are `aria-hidden`. A marquee contains no essential information, has a visible pause/resume control, and becomes a static non-duplicated row under reduced motion.

### Responsive Shell

| Width | Contract |
|-------|----------|
| 320px | 16px gutters. Header uses the wordmark on the first row and a visible two-column, two-row navigation grid below it; no hidden destination, clipped label, menu-only discovery, or horizontal page scroll. Sections are one column. |
| 768px | 24px gutters. Wordmark and four navigation links share one row. Editorial sections remain one column unless both columns retain at least 320px usable width. |
| 1440px | 32px gutters inside a 1400px maximum container. Home may use asymmetric two-column compositions; route reading regions remain bounded. |

At every width, text remains at contracted sizes, actions remain visible, and zoom/reflow does not require horizontal page scrolling. Only deliberately horizontal `ScrollRail` regions may overflow within their own labelled container.

## Global Interaction and Accessibility Contract

### Keyboard and Focus

- Every control is reachable in DOM order and works without pointer input. Interactive targets are at least 44px square.
- `Enter` activates links and buttons; `Space` activates buttons. Native semantics supply these behaviors.
- Focus indicators are visible on every semantic fill and are never clipped by overflow containers.
- Opening a modal drawer moves focus inside; focus stays contained until close. Closing returns focus to the invoking control when it still exists, otherwise to the route heading or results region.
- `Escape` closes the topmost dismissible overlay. A visible close button is always available.
- Overlay content contains its own scroll, prevents background scroll, and contains scroll chaining.
- Route and async focus changes do not steal focus from a user who is reading, selecting text, or composing a question.
- Async status uses a concise `aria-live="polite"` status node. Streaming answer tokens are not individually announced.

### Availability State Language

Every applicable state has a visible text label, explanation, remaining-safe behavior, and recovery action. Icons and colors are secondary.

| State | Meaning and required presentation |
|-------|-----------------------------------|
| `unknown` | Truth has not been established; say what evidence is missing and do not imply failure or zero. |
| `unavailable` | The source or public capability is not available; keep unaffected navigation/actions usable. |
| `stale` | Data has a known older observation time; show that time and avoid presenting it as current. |
| `partial` | Some expected evidence arrived; name the available and missing parts. |
| `empty` | A valid query returned no public records; offer the next valid action. |
| `permission-denied` | Reserved for future protected surfaces; a public route must not reveal that a protected record exists. |
| `error` | Name the public failure boundary and one safe retry or return path without provider detail. |
| `offline` | Network is unavailable; retain already rendered public content and offer retry. |
| `unmapped` | Evidence exists but no verified timeline coordinate exists; omit timestamp affordances. |
| `conflicted` | Two public evidence values disagree; name the conflict and do not choose silently. |
| `measured-zero` | A source explicitly measured zero; render numeral `0` with the named source/scope, never as a substitute for missing data. |

## Motion Contract

| Token | Value | Use |
|-------|-------|-----|
| `duration-fast` | 120ms | Hover, focus, press feedback |
| `duration-default` | 200ms | Disclosure and inline state continuity |
| `duration-slow` | 320ms | Drawer enter/exit only |
| `ease-out` | `cubic-bezier(0,0,.2,1)` | Entry and feedback |
| `ease-in` | `cubic-bezier(.4,0,1,1)` | Exit |
| `ease-in-out` | `cubic-bezier(.4,0,.2,1)` | State continuity |

- Animate transform and opacity only unless a measured exception is recorded. Never use `transition: all`.
- Every animation is interruptible. Loading uses geometry-matched skeletons, not indefinite generic spinners.
- Marquee, sparkle, card-lift, custom cursor, smooth scroll, drawer motion, and graph simulation respond immediately to `prefers-reduced-motion` changes.
- Reduced motion removes loops, custom-cursor interpolation, parallax, card translation, and graph simulation; large transitions become a static swap or a fade no longer than 120ms. `ScrollRail` uses immediate native scrolling.
- Graph motion stops after layout settles and while offscreen even when motion is allowed.

## Route Contract — `/episodes`

### Page Composition

1. Page heading, public catalogue count, and public source link.
2. One labelled section per existing show, each with count and `ScrollRail`.
3. Episode cards containing public thumbnail, title, show context, duration, and views only when available.
4. URL-backed `EpisodeDrawer` for public detail and transcript evidence.
5. Empty, invalid-selection, loading, untimed, unavailable, offline, and safe-error surfaces where applicable.

### `ScrollRail` Interaction Contract

- Use a labelled `section` containing visible `previous episodes` and `next episodes` buttons followed by a native `overflow-x: auto` rail with mandatory scroll snap.
- Native touch, trackpad, mouse-wheel, and scrollbar behavior is the baseline. Pointer dragging is optional and never the only path.
- Tab traverses controls and episode cards in DOM order. When the rail itself has focus, Left/Right moves one snap item and Home/End moves to the first/last item. Cards activate with Enter/Space.
- Previous/next moves one visible snap item while keeping focus on the control. Buttons expose disabled state at the corresponding edge; do not announce every scroll movement.
- Motion allowed uses the default 200ms continuity. Reduced motion uses immediate scrolling.
- Each card is 272px at 320px, 280px at 768px, and 300px at 1440px, never wider than `calc(100vw - 48px)`.
- Start, middle, and end positions are deterministic proof states. Content order is stable and fixture-controlled.

### URL-Backed `EpisodeDrawer`

- The Phase 1 deep link is `/episodes?episode=<public-video-id>` because `/episodes` is the only episode route that exists in the current repository; preserve every unrelated query parameter byte-for-byte where URL encoding allows.
- A future `/episodes/:id` or `episodes/[episodeId]/` path-segment route requires a separate explicit contract decision plus tested compatibility or redirect behavior. It is not created or implied by this phase.
- Activating a card pushes the selected URL. Browser Back closes the drawer and Browser Forward reopens it. Refresh and shared links reopen the same public episode.
- The drawer is a labelled modal dialog with `aria-modal="true"`, a visible `close episode` button, Escape and backdrop dismissal, contained scroll, background inertness, and focus containment.
- On open, focus the drawer title (`tabindex="-1"`) so long content begins with context. Do not autofocus a source or Ask WTF action.
- Same-page close returns focus to the invoking episode card and retains rail position. Direct/shared-load close removes only the `episode` parameter with replace semantics and focuses the Episodes heading/results region.
- An unknown public episode ID opens no drawer. Show a non-leaking unavailable notice, preserve other query parameters, and focus the notice only when the URL was loaded directly.
- The drawer contains title, show, thumbnail, duration, views when available, transcript availability/context/excerpt, verified source and timestamp links, and the existing Ask WTF entry point. It never contains workflow, owner, private asset, permission, dossier, budget, lead, brief, health, or production fields.
- Timestamp links render only for verified timing. Untimed transcript text has no play icon, timestamp chip, guessed offset, or time query parameter.

### Drawer Responsive Layout

| Width | Contract |
|-------|----------|
| 320px | Full viewport sheet, 16px padding, sticky close/header, transcript scroll inside the sheet, no page overflow. |
| 768px | Right-edge drawer, width `min(560px, 88vw)`, bounded ink edge and one overlay. |
| 1440px | Right-edge drawer, maximum 640px, with a 65–72ch transcript measure and visible underlying list context. |

Required deterministic evidence: page ready; rail start/middle/end; keyboard card activation; drawer open with transcript loading, timestamped, untimed, unavailable, invalid ID, and safe-error fixtures; Escape, close, Back, Forward, refresh, focus return; reduced motion; and each state at 320, 768, and 1440 where applicable.

## Route Contract — `/connections`

### Composition and Parity

1. Page heading and a short explanation that nodes are recurring public themes and ideas, not verified people/company or operator records.
2. A visual canvas graph and an immediately adjacent equivalent semantic list on the same page.
3. Public node detail containing label, category, episode count, public source episodes, and verified public links.
4. Public connection detail containing both node labels and the shared-episode count.

The canvas and list consume the same immutable `PublicConnectionProjection`. Parity is exact by stable node ID and edge key:

- Every canvas edge has one semantic relationship entry with both endpoint IDs and the same shared count.
- Canvas or list selection updates the same public detail region; selected state is visible through text/boundary and `aria-current` or `aria-selected` as appropriate, not color alone.
- The canvas is `aria-hidden="true"` and never enters the tab order. The semantic list supplies all meaning and actions to assistive technology and keyboard users.
- No graph or list field exposes tasks, owners, leads, budgets, briefs, health, production state, permissions, or operator interaction state.

### Interaction, Motion, and Width

- The semantic list uses native disclosure buttons or links with 44px targets and predictable DOM order. Enter/Space toggles details; source links remain ordinary links.
- The visual graph may support pointer hover, drag, and selection as enhancement only. No required content appears only on hover.
- With motion allowed, start from a deterministic seeded layout, settle, then stop animation. Pause while offscreen. With reduced motion, render the final seeded layout immediately and schedule no animation frames.
- At 320px, use one column: bounded canvas first, full semantic list second, then connection entries. Details never overlay or clip the list.
- At 768px, canvas and list remain stacked so each has readable width.
- At 1440px, canvas and semantic list may form a 3:2 two-column region while both remain visible in the same viewport section.

Required deterministic evidence: graph and list ready, exact parity, selected node from canvas, selected node from list keyboard use, reduced-motion stable graph with zero continuing RAF work, empty projection, safe error, narrow layout, and public forbidden-field scan at all three widths.

## Route Contract — `/chat` Ask WTF

### Composition

1. Page heading `ask wtf` and a short evidence promise.
2. Conversation region with distinct user question, grounded synthesis, abstention, safe error, and source containers.
3. Persistent labelled `ask the catalogue` composer and `ask wtf` submit action.
4. Source panel kept visible with each completed grounded answer.

Remove `ModelPicker`, public model selection, model labels, retrieval engine names, chunk counts, fallback implementation labels, and retry-by-model copy. A diagnostic model control may exist only in an internal feature-gated surface outside this public route.

### Interaction and State

- `/chat?q=...` retains its current one-time auto-submit meaning. Preserve unrelated supported query parameters and do not submit twice after hydration.
- The empty example is visible text and never auto-submits. The composer has a persistent visible label, not placeholder-only labelling.
- Submit is disabled for blank input and while a request is active. Enter submits the single-line composer; composition events must complete before submission.
- Loading reserves the assistant response geometry and exposes `looking through the catalogue` in one polite live status. Do not announce each streamed token.
- Incremental text renders without moving keyboard focus. Auto-scroll only while the reader is already near the end; once the reader scrolls upward, preserve their position.
- Grounded answers visually separate synthesis from sources. Citation numbers match the source list and each source names the public episode; a verified timestamp appears only when supplied by the accepted source field.
- Ungrounded/fallback responses present the explicit label `the catalogue doesn't support that claim`; they do not fabricate a citation, timestamp, owner, role, or certainty.
- Safe errors retain the accepted `/api/chat` public error text and offer `try again`. Provider responses, stack traces, secret names/values, request IDs, and model routing remain absent.
- `retry answer` repeats the accepted request path without exposing or selecting a model. Offline state keeps the composed question available for manual retry.

## `/api/chat` Compatibility Seam

The UI redesign does not alter the accepted request validation, last-eight-message handling, accepted question limit, response body consumption, streaming/chunk behavior, citation mapping, source fields, status codes, content types, required headers, no-store policy, or safe error shapes. Visual tests use a deterministic local Worker-shaped stub but assert the current public fields:

`n`, `video_id`, `title`, `score`, optional `t`, optional `time`, and `url`, plus `X-Sources`, `X-Model`, `X-Fallback`, `Content-Type`, and `Cache-Control` where the accepted contract supplies them.

The UI may consume `X-Model` and `X-Fallback` for compatibility logic, but it does not display model infrastructure. Any behavior ambiguity, including exact first-byte/chunk cadence in the dirty accepted baseline, must be captured and owner-approved before `/chat` implementation. This specification does not silently choose a new API behavior.

| `/connections` | Public node ID, label, category, episode count, public episode IDs/titles/source links, edge endpoint IDs, shared count |
| `/chat` | The visitor's current question in their own session, safe public answer text, and allowlisted source fields `n`, `video_id`, `title`, `score`, `t`, `time`, `url` |

Forbidden everywhere: internal tasks, owners, leads, budgets, briefs, production stage or health, operator permissions, private assets, raw provider payloads, credentials, `.env` material, native session identifiers, embedded private links, machine-local paths, stack traces, model-routing controls, and private prompt/response logs.

Proof fixtures contain synthetic public-shaped text and dummy secrets only. Browser bundles, RSC/rendered payloads, logs, errors, snapshots, Storybook output, Lighthouse output, Playwright traces, and planning artifacts are scanned for prohibited classes. Test evidence never sends fixtures to a live model or external service.
