1. Create `cloudflare/src/ingest/version-staging.ts`:
   - Implement `stageAndActivateTranscriptVersion(db: D1Database, vectorize: VectorizeIndex, ai: Ai, payload: TranscriptIngestJobPayload, segments: DiarizedSegmentInput[]): Promise<{ versionId: string; status: 'activated' | 'skipped_unchanged' }>`.
   - **Idempotency Guard**:
     - Compute SHA-256 hash of canonical normalized segment text and timestamps.
     - Query active version: `SELECT id, content_sha256 FROM transcript_versions WHERE episode_id = ? AND is_active = 1`.
     - If active version has identical `content_sha256`, log idempotency match and return `{ versionId: active.id, status: 'skipped_unchanged' }`.
   - **Version Staging**:
     - Determine next version number: `SELECT COALESCE(MAX(version_number), 0) + 1 AS next_ver FROM transcript_versions WHERE episode_id = ?`.
     - Generate `versionId = 'txv_' + ulid()`.
     - Insert into `transcript_versions` with `state = 'staging'`, `is_active = 0`, `content_sha256`, `total_segments = segments.length`.
     - Batch insert segments into `transcript_segments` with unique `(transcript_version_id, segment_index)`.
   - **Text Chunking & Embedding**:
     - Implement sliding window chunker: chunk segments into ~1,000 character windows (~250 tokens) with 150 character overlap, recording `start_sec`, `end_sec`, `start_segment_id`, `end_segment_id`.
     - Generate embeddings via Workers AI `@cf/baai/bge-large-en-v1.5` in batches of 8 chunks.
     - Construct Vectorize records:
       - `id`: `vec_${payload.episodeId}_v${next_ver}_${chunk.id}`
       - `values`: 1024-dimensional embedding vector
       - `metadata`: `{ episodeId: payload.episodeId, versionId, versionNumber: next_ver, chunkId: chunk.id, languageCode: chunk.languageCode, startSec: chunk.startSec, endSec: chunk.endSec }`
     - Upsert vectors into Vectorize (`vectorize.upsert(vectors)`).
     - Insert chunk records into D1 `transcript_chunks` with `is_active = 0`.
   - **Atomic Activation Transaction**:
     - Execute batch D1 transaction:
       ```sql
       -- 1. Archive prior active versions
       UPDATE transcript_versions SET is_active = 0, state = 'archived' WHERE episode_id = ? AND is_active = 1;
       -- 2. Activate new version
       UPDATE transcript_versions SET is_active = 1, state = 'active', activated_at = CURRENT_TIMESTAMP WHERE id = ?;
       -- 3. Deactivate old chunks
       UPDATE transcript_chunks SET is_active = 0 WHERE transcript_version_id IN (SELECT id FROM transcript_versions WHERE episode_id = ? AND is_active = 0);
       -- 4. Activate new chunks
       UPDATE transcript_chunks SET is_active = 1 WHERE transcript_version_id = ?;
       ```
   - **Vector Tombstoning**:
     - Query all obsolete chunk vector IDs belonging to archived versions for this episode.
     - Call `vectorize.deleteByIds(obsoleteVectorIds)`.
     - Mark archived transcript version `state = 'tombstoned'`.

2. Create `cloudflare/test/version-staging.spec.ts` with Vitest testing:

   - Re-ingesting a shortened transcript properly tombstones the orphaned tail vectors in Vectorize.
   - Concurrent retrieval assertion: vector search filtering by `versionId` or active chunk IDs never returns cross-version mixed passages.

<threat_model>
## Assets
- Diarized transcript evidence and speaker attribution.
- Vector search index (`wtfmedia-catalogue-v1`) integrity and embedding freshness.
- Asynchronous ingestion queue state and worker execution budget.

## Trust Boundaries
| Boundary | Description |
|---|---|
| R2 Storage → Queue Consumer | Ingested transcript payloads must be validated for well-formed timing, non-empty text, and valid speaker labels. |
| Ingestion Queue → Vectorize / D1 | Vector embeddings and D1 rows must be staged in non-active state to prevent partial/failed ingestion pollution. |
| Version Cutover → Vector Search | Atomic transition must guarantee search queries never retrieve mixed chunks across different transcript versions. |
