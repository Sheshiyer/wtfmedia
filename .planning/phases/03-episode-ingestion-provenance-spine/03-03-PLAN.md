  <name>Task 1: Implement read-only YouTube Data API v3 adapter with ETag caching in KV (WTFMEDIA_STATE)</name>
  <files>cloudflare/src/ingest/youtube-adapter.ts, cloudflare/tests/youtube-ingest.test.mjs</files>
  <read_first>cloudflare/wrangler.jsonc; cloudflare/src/scheduled.ts; .planning/REQUIREMENTS.md PROV-10, INTG-07; .agents/explorer_pipeline_survey/handoff.md Section 2.1.A</read_first>
  <action>Create `cloudflare/src/ingest/youtube-adapter.ts` implementing a quota-optimized YouTube Data API client:
    1. Channel Uploads Playlist extraction:
       - Transform Channel ID (e.g. `UC_6vmsXQvU_Y1O6iFqH1_Xw`) to Uploads Playlist ID by replacing `UC` prefix with `UU` (`UU_6vmsXQvU_Y1O6iFqH1_Xw`).
       - Call `GET https://www.googleapis.com/youtube/v3/playlistItems?part=snippet,contentDetails&playlistId=${uploadsPlaylistId}&maxResults=50` with header `If-None-Match: <cached_etag>`.
    2. ETag Caching in KV:
       - Check KV `env.WTFMEDIA_STATE` key `yt:etag:${channelId}`.
       - If YouTube API returns HTTP `304 Not Modified`: log "ETag match, 0 new items", and return early with `{ changed: false, items: [] }` (0 DB writes).
       - If YouTube API returns HTTP `200 OK`: store new `ETag` in KV `env.WTFMEDIA_STATE` key `yt:etag:${channelId}`.
    3. Batch Video Details Extraction:
       - Collect video IDs from playlist items (up to 50 IDs per batch).
       - Call `GET https://www.googleapis.com/youtube/v3/videos?part=snippet,contentDetails,statistics&id=${videoIds.join(',')}` (costs exactly 1 quota unit for 50 videos).
    4. Quota and Error Handling:
       - Catch HTTP 403 / 429 quota exhaustion errors gracefully; set backoff timestamp in KV `yt:quota_backoff_until` and return structured failure result without uncaught exceptions.
       - Require an owner-approved OAuth bearer authorization from the external connection boundary. When unavailable, return the documented connection-required state before any API request, job, audit mutation, or response containing account information.</action>
  <acceptance_criteria>
    - Adapter consumes <= 2 quota units per 50-video page compared to 100+ units for `search.list`.
    - HTTP 304 response terminates processing immediately with zero database writes.
    - Quota exhaustion or network error triggers backoff and logs clean error envelope to `ingestion_jobs`.
  </acceptance_criteria>
  <verify>
    <automated>cd cloudflare && npm test -- youtube-ingest --grep adapter</automated>
    <expected>Exit 0; adapter tests pass for 200 OK, 304 Not Modified, batch ID chunking, and 429 quota backoff.</expected>
  </verify>
  <done>Read-only YouTube Data API client is operational with ETag caching and quota protection.</done>

  <action>Implement metadata parsers and scheduled synchronization worker:
    1. Metadata Parser (`cloudflare/src/ingest/youtube-parser.ts`):
       - `parseIsoDuration(durationStr: string): number`: Converts ISO 8601 strings (e.g. `PT1H23M45S`, `PT58M10S`, `PT45S`) to integer seconds.
       - `parseChapters(description: string, durationSeconds: number): Chapter[]`: Scans description for timestamp patterns (`HH:MM:SS` or `MM:SS`) followed by chapter titles, validates monotonicity, assigns start/end seconds, and enforces bounds.
       - `extractGuestAndShow(title: string, description: string, channelTitle: string)`: Extracts guest names, IP classification, and show category (`Podcasts by WTF`, `People by WTF`, `WTF is Finance`, `Special Episodes`, `WTF Online`).
    2. Scheduled Cron Sync (`cloudflare/src/scheduled.ts`):
       - Implement `syncYouTubeChannels(env: Env, db: D1Database)`:
         - Fetches active channels from configuration.
         - For each video item:
           - Resolves existing episode via `episode_external_identities` (`platform = 'youtube'`, `external_id = videoId`).
           - If existing: updates metadata, duration, description, chapters, and thumbnail.
           - If new: generates canonical `ep_<ulid>`, calls `upsertEpisode` and `recordExternalIdentity` with `is_primary = 1`.
         - Records job execution result in `ingestion_jobs` (`job_type = 'youtube_metadata_sync'`).
    3. Manual Trigger & Ops Router (`cloudflare/src/ops-router.ts`):
       - Add endpoint `POST /ops/api/ingest/youtube-sync` requiring `admin` or `super_admin` role.
       - Triggers immediate channel sync and logs `audit_events` action `ingest_trigger`.
    4. Worker Cron Declaration (`cloudflare/wrangler.jsonc`):
       - Add `"triggers": { "crons": ["0 */6 * * *"] }` (runs every 6 hours).
    5. Test Suite (`cloudflare/tests/youtube-ingest.test.mjs`):
       - Test parser across sample WTF episode descriptions with various chapter formats.
       - Test idempotency: Run sync 3 consecutive times with the same mock fixtures and assert exactly 0 duplicate episode records are created.</action>
  <acceptance_criteria>
    - ISO 8601 duration parser accurately parses short and multi-hour durations.
    - Chapter parser outputs valid JSON array of `{ title, start_sec, end_sec }` with non-overlapping, strictly increasing ranges.
    - Running channel sync repeatedly on identical data produces 0 duplicate records in `episodes` and `episode_external_identities`.
    - Manual endpoint `/ops/api/ingest/youtube-sync` requires `admin`/`super_admin` and returns structured job status.
  </acceptance_criteria>
