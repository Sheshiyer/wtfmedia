    - Path builder function `getAssetR2Key(episodeId: string, assetType: SourceAssetType, contentSha256: string, ext: string)`:
      - Uncut audio: `episodes/${episodeId}/assets/uncut/audio_${contentSha256.slice(0, 16)}.${ext}`
      - Uncut video: `episodes/${episodeId}/assets/uncut/video_${contentSha256.slice(0, 16)}.${ext}`
      - Published audio: `episodes/${episodeId}/assets/published/audio_${contentSha256.slice(0, 16)}.${ext}`
      - Captions / Subtitles: `episodes/${episodeId}/assets/captions/sub_${contentSha256.slice(0, 16)}.${ext}`
      - Transcripts: `episodes/${episodeId}/transcripts/txv_${contentSha256.slice(0, 16)}.json`
      - Sidecar metadata: `episodes/${episodeId}/metadata/manifest_${contentSha256.slice(0, 16)}.json`
    - MIME-type validation whitelist: `audio/flac`, `audio/mp4`, `audio/mpeg`, `audio/ogg`, `audio/wav`, `video/mp4`, `text/vtt`, `application/x-subrip`, `application/json`.
    - File size limits by asset type: Uncut video <= 5GB, Uncut audio <= 500MB, Captions/Transcripts <= 50MB, Metadata <= 10MB.
    - Content hashing helpers: `computeSha256(data: ArrayBuffer | Uint8Array): Promise<string>` and streaming SHA-256 verifier.
    - Implement path parser `parseAssetR2Key(key: string)` ensuring keys match the strict regex pattern and reject traversal attempts (`..`, `//`, absolute paths).</action>
  <acceptance_criteria>
    - Storage keys follow deterministic, collision-resistant naming based on episode ULID and content SHA-256.
    - Path generator and parser reject any path containing relative traversal sequences (`..`), null bytes, or invalid extensions.
    - Disallowed MIME types and oversized payloads are rejected before storage allocation.
  </acceptance_criteria>

<task type="auto" tdd="true">
  <name>Task 2: Implement /ops/api/assets/upload-intent and /ops/api/assets/confirm-upload Worker endpoints gated by Phase 2 Zero Trust policy boundary</name>
  <files>cloudflare/src/assets/upload-handler.ts, cloudflare/src/ops-router.ts, cloudflare/src/auth/policy.ts, cloudflare/tests/asset-upload.test.mjs, web/tests/security/phase3-threat-results/03-02.json</files>

  <action>Implement secure upload coordinator endpoints in `cloudflare/src/assets/upload-handler.ts` and mount them in `cloudflare/src/ops-router.ts`:
    1. Extend `cloudflare/src/auth/policy.ts`: Add actions `assets:create`, `assets:upload`, `assets:confirm` to `super_admin`, `admin`, and `editor` role policies.
    2. Endpoint `POST /ops/api/assets/upload-intent`:
       - Requires valid Cloudflare Access session and active operator with `assets:create` capability.
       - Validates input body: `{ episodeId, assetType, byteSize, mimeType, expectedSha256, ext }`.
       - Validates `episodeId` exists in D1 database `episodes` table.
       - Signs an HMAC-SHA256 upload ticket payload: `{ ticketId, episodeId, assetType, targetKey, expectedSha256, byteSize, operatorId, expiresAt: Date.now() + 15 * 60 * 1000 }` using `env.EDGE_SHARED_SECRET`.
       - Returns opaque ticket and target handle: `{ uploadTicket, assetId: 'ast_' + ulid(), expiresAt }` without leaking bucket ARN or local paths.
    3. Endpoint `PUT /ops/api/assets/upload-stream`:
       - Accepts streaming binary upload with header `X-Upload-Ticket: <ticket>`.
       - Validates HMAC signature and ticket expiry (< 15 mins).
       - Streams bytes directly to `env.CATALOGUE.put(targetKey, request.body)` while calculating running SHA-256 hash.
       - Validates byte count <= limit and computed SHA-256 === `expectedSha256`. If mismatched, deletes object from R2 and returns 400 Bad Request.
    4. Endpoint `POST /ops/api/assets/confirm-upload`:
       - Receives `{ uploadTicket, assetId, durationSeconds, authority }`.
       - Verifies ticket and verifies object existence in R2 via `env.CATALOGUE.head(targetKey)`.
       - Calls `createSourceAsset` in D1 (`availability = 'available'`, `storage_driver = 'r2'`).
       - Writes audit log event `asset_upload` to D1 `audit_events` with operator context.
    5. Privacy Scan: Assert that no response payload contains internal bucket names, server file system paths, or raw capability tokens.</action>
  <acceptance_criteria>
    - Unauthenticated requests or operators with insufficient privileges receive 401/403 denials.
    - Tampered or expired upload tickets fail HMAC verification and reject uploads.
    - Mismatched SHA-256 hashes immediately abort and clean up R2 staging objects.
    - Zero private storage paths, hostnames, or credentials appear in API responses or client-facing DTOs (QUAL-05, QUAL-12).
  </acceptance_criteria>
